# Glossary

This folder contains the key terms used throughout **Start Docs-as-Code with Me**.

The glossary is intended to help readers understand technical terms as they encounter them during the learning journey.

## What you will find here

The glossary includes terms related to:

- Docs-as-Code
- Technical writing
- Git and GitHub
- Markdown
- Docusaurus
- API documentation
- Automation
- Artificial intelligence
- Developer tools
- Documentation workflows

## How the glossary is maintained

New terms are added as they are introduced in the course.

Definitions are kept short and practical. The aim is to explain a term in the context of documentation work rather than provide a formal technical definition.

If a term has a different meaning in a specific tool or technology, the definition should make that context clear.

## Glossary terms

See **[Glossary Terms](./glossary-terms.md)** for the complete list.

## Why maintain a glossary?

A shared glossary helps technical writers:

- Use terminology consistently.
- Understand unfamiliar technical terms.
- Avoid unnecessary variation in wording.
- Support consistent documentation across projects.
- Build a common vocabulary with developers and other subject matter experts.

> **Documentation practice**
>
> A glossary is not just a list of definitions. It is also a useful tool for maintaining terminology consistency across a documentation set.

---

## Contribution

When adding a new term:

1. Check whether the term already exists.
2. Use the terminology used by the relevant product or technology.
3. Keep the definition short and clear.
4. Add context when the meaning depends on a specific technology.
5. Avoid defining a term using another unexplained technical term where possible.

The glossary should grow with the learning content rather than become a separate project to maintain.
