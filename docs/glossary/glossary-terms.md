## A

| Term | Definition |
| --- | --- |
| Accessibility | Designing content so that people with different abilities can use and understand it. |
| Accountability | The clear assignment of one owner for each decision, so that someone is responsible for its outcome. |
| Action | A reusable step, published by GitHub or others, that a workflow runs with the `uses` keyword. |
| Agentic AI | An AI approach in which the AI chooses its next steps within defined limits, using tools and checks. |
| AI | Artificial intelligence used to assist with tasks such as analysis, writing, and coding. |
| AI agent | An AI model that completes a task in steps, using inputs, tools, and outputs. |
| AI chat | A panel in an AI-enabled editor where you ask questions about files and request proposed changes. |
| Alt text | A short description of an image that screen readers read aloud, describing its purpose. |
| Anchor | A named location on a page, such as a heading, that a link can point to with a # symbol. |
| API key | A secret value used to authenticate access to an API or service. |
| Argument | A value that a command uses, such as a file name or a script name. |
| Artifact | A file or set of files that a pipeline produces and stores, such as a built site. |
| Audience | The group of readers that a piece of content is written for, such as customers or support teams. |
| Automation | A set of steps that runs without manual action, using rules that people define. |
| Autonomy level | The amount of action an AI step may take without a person, from suggest only to publish. |

## B

| Term | Definition |
| --- | --- |
| Base URL | The path under a domain where a site is served, such as /Start-Docs-as-Code-with-Me/. |
| Baseline | The measurement of a task before a change, used as the reference for comparing results after it. |
| Blockquote | A Markdown element used to visually distinguish quoted or highlighted content. |
| Branch | A separate line of development within a repository. |
| Brief | A short written set of audience, purpose, approved facts, and constraints, given to a writer or an AI tool before a page is drafted. |
| Broken link | A link whose target page, file, or anchor does not exist. |
| Build | The process of generating the output required to publish or run a project. |
| Bulleted list | A list used when the order of items does not matter. |

## C

| Term | Definition |
| --- | --- |
| Callout | A visually highlighted section used to draw attention to specific information. |
| Capstone | A final project or lesson that combines the skills from a module into one piece of work. |
| Case study | A detailed account of a real project, its decisions, its trade-offs, and its outcome. |
| Checkpoint | A defined point in a workflow where a person must approve before the work continues. |
| CI/CD | Automated processes used to build, test, and deliver software or documentation changes. |
| Claude Code | An AI coding assistant that runs in a terminal and works with the files in a project folder. |
| CLAUDE.md | A project memory file that Claude Code reads when a session starts, used to store project rules. |
| Clone | Creates a local copy of a remote repository. |
| Code block | A separate block used to display commands, code, configuration, or other technical content. |
| Code fence | The three backticks used to open and close a Markdown code block. |
| Command | An instruction entered into a terminal or command-line interface. |
| Command Palette | A VS Code interface that provides access to commands and features. |
| Command Prompt | The Windows terminal application. |
| Commit | A saved set of changes in a Git repository. |
| Configuration | Settings that control how an application or system behaves. |
| Consistency | Using the same terminology, structure, and conventions throughout a documentation set. |
| Container | A running, isolated environment created from a Docker image. |
| Continuous delivery | A practice in which each checked change is prepared so that it can be published at any time. |
| Continuous deployment | A practice in which each checked change is published automatically. |
| Continuous integration | A practice in which each change is built and checked as soon as it is added. |
| Contrast ratio | A measure of how different a text color is from its background, used to judge whether text is readable. |
| Counter-example | An output that you do not want an AI tool to produce, used to show what to avoid. |
| cSpell | A spell checker extension for VS Code that reads a custom word list from the project settings. |
| Cursor | An AI-powered code editor used to work with software projects and files. |

## D

| Term | Definition |
| --- | --- |
| Danger | A callout used to identify a serious or potentially destructive action. |
| Data classification | A grouping of content by its sensitivity, which sets what may be shared with a tool. |
| Defect | An error in content, code, or a process that causes a reader or a check to fail. |
| Defect escape rate | The share of errors found after publication, compared with the number of pages published. |
| Dependency | Software or a package that another application or project requires. |
| Deploy | To publish a site or a change to a live environment where readers can use it. |
| Deterministic step | A step that always produces the same result for the same input. |
| Docker | A platform for building, running, and managing applications in containers. |
| Docker CLI | The command-line interface used to interact with Docker. |
| Docker Desktop | The desktop application that provides Docker tools on Windows, macOS, and Linux. |
| Docker Engine | The technology that runs and manages Docker containers. |
| Docker Hub | Docker's public registry for container images. |
| Dockerfile | A text file containing instructions for building a Docker image. |
| Docs-as-Code | A documentation approach that uses software development tools and workflows to create, manage, review, and publish documentation. |
| Docusaurus | A framework used to build documentation websites from content such as Markdown and React components. |

## E

| Term | Definition |
| --- | --- |
| Editor | The area where you view and edit files. |
| Environment | A named deployment target, such as github-pages, that can have its own rules and required reviewers. |
| Event | Something that happens, such as a push or a file save, that can start an automated task. |
| Example pair | An input and the output that you want for it, used to teach an AI tool a pattern. |
| Explorer | The part of the editor that displays project files and folders. |
| Extension | An add-on that provides additional functionality in VS Code. |
| External link | A link to a page on another website, which the build does not check by default. |

## G

| Term | Definition |
| --- | --- |
| Git | A distributed version control system used to track changes to files. |
| `.git` | The directory where Git stores repository information. |
| Git configuration | Settings that control how Git behaves. |
| Git diff | A command that shows the changes between your working files and the last commit, line by line. |
| Git hook | A script that Git runs automatically at a point in its workflow, such as before a commit. |
| Git repository | A folder managed by Git that contains files and their version history. |
| GitHub | A platform for hosting Git repositories and collaborating on projects. |
| GitHub Actions | GitHub's automation platform for running workflows in response to repository events. |
| GitHub Desktop | A graphical application for working with GitHub repositories. |
| GitHub Pages | A GitHub service that hosts static websites published from a repository. |
| Governance | The rules that define where AI helps, what it may see, who checks results, and who is accountable. |
| Guardrail | A rule that limits what an agent may change or decide. |

## H

| Term | Definition |
| --- | --- |
| Hallucination | An AI output that states a fact, value, or source that sounds plausible but is not supported by the input or a real source. |
| Heading | A piece of text used to organize the structure of a document. |
| Hook | An automated action that runs when a specific event happens. |
| Horizontal rule | A visual separator created with Markdown syntax. |
| HTTPS | A secure web protocol that can be used for Git repository connections. |
| Human-in-the-loop | A review model in which a person approves the result before it is used. |

## I

| Term | Definition |
| --- | --- |
| Image | A package containing the files and configuration needed to create a container. |
| Important | A callout used when information requires particular attention. |
| Incident | An event in which an error, data exposure, or unapproved change reaches readers or a system, and needs a response. |
| Inclusive language | Wording that avoids assumed knowledge, idioms, and terms that may exclude readers. |
| Inline code | A short technical value displayed within normal text. |
| Inline edit | A change that an AI tool proposes within the open file, which you accept or reject. |
| Input | The data or file that an agent receives. |
| Integrated Terminal | A terminal built into VS Code. |
| Internal link | A link to a page or file within the documentation site, which the build checks. |

## L

| Term | Definition |
| --- | --- |
| Language identifier | The value after the opening code fence that identifies the language used in the code block. |
| Linter | A tool that checks a file against a set of rules, and reports errors and warnings. |
| Local repository | A Git repository stored on your computer. |
| Locale | A language and region setting, such as en for English, that a site uses to show its content. |
| Localization | Adapting translated content for a region, including formats, examples, and screenshots. |
| LTS | Long-Term Support; a release intended for longer-term stability and support. |

## M

| Term | Definition |
| --- | --- |
| Maintainability | How easily documentation can be updated and kept accurate over time. |
| Markdown | A lightweight markup language commonly used for technical documentation. |
| Markdown preview | A rendered view of a Markdown file, shown next to or in place of its source. |
| Markdown source | The Markdown text that a writer edits. |
| MCP | Model Context Protocol, a standard way for an AI tool to connect to an external system through a server. |
| MDX | Markdown with support for JSX and React components. |
| Metric | A measured value, defined with a formula, a unit, and a source, used to track a process. |
| Migration | Moving content from one system or format into another, while keeping its meaning, links, and structure. |
| Mock data | Fictional data that stands in for real data during testing or demonstrations. |
| Multi-agent workflow | A workflow that divides a task across several agents, each with one role. |

## N

| Term | Definition |
| --- | --- |
| Node.js | A runtime environment used to run JavaScript applications outside a web browser. |
| `node_modules` | The directory where project dependencies installed by npm are stored. |
| npm | The Node Package Manager used to install and manage packages. |
| npm install | An npm command used to install project dependencies. |
| npm run | An npm command used to run scripts defined by a project. |
| npm script | A named shortcut in package.json that runs a longer command, such as npm run build. |
| Numbered list | A list used when items need to be followed in a specific order. |

## O

| Term | Definition |
| --- | --- |
| Option | A setting that changes how a command runs, often written with two dashes, such as --port. |
| `origin` | The conventional name for the main remote repository. |
| Output | The data or file that an agent produces for the next step. |

## P

| Term | Definition |
| --- | --- |
| Package | A reusable software component that can be installed into a project. |
| `package.json` | A project file that contains information about a Node.js project, including scripts and dependencies. |
| Paragraph | A group of sentences that presents a related idea. |
| PATH | An operating system setting that allows command-line applications to be found from a terminal. |
| Permission prompt | A request from Claude Code that asks you to approve a command or file change before it runs. |
| pip | The package installer used to install Python packages. |
| Pipeline | A series of automated steps that run in order, where each step depends on the one before it. |
| Placeholder | Example text that the reader replaces with their own value. |
| Plugin | A package that adds features to an AI tool, such as commands, skills, connections, or hooks. |
| PowerShell | A Windows command-line shell used to run commands and scripts. |
| Preferred term | The one word or phrase that a project chooses to use for a concept, recorded with its variants to avoid. |
| Procedure | A set of instructions that helps a reader complete a task. |
| Prompt | The written instruction that you give an AI tool. |
| Prompt engineering | Writing, testing, and versioning prompts so that results are consistent and easy to check. |
| Prompt injection | Text written to look like an instruction, placed in source content to change how an AI tool behaves. |
| Pull | Gets changes from a remote repository and updates the local repository. |
| Pull Request | A request to review changes before they are merged into a shared repository. |
| Push | Sends local commits to a remote repository. |
| Python | A programming language used for automation, software development, data processing, and many other tasks. |
| Python interpreter | The software that reads and executes Python code. |
| Python script | A file containing Python code that can be executed by the Python interpreter. |

## R

| Term | Definition |
| --- | --- |
| Redirect | A rule that sends a reader from an old address to the new page, so that old links still work. |
| Reference output | An example of the final format and tone that an AI tool should produce. |
| Registry | A service used to store and distribute container images. |
| Release note | A document that tells readers what changed in a release, what they must do, and where to find more information. |
| Remote | A reference to another Git repository, commonly a GitHub repository. |
| Remote repository | A repository hosted somewhere other than your local computer, such as GitHub. |
| Rendered content | The formatted result produced when Markdown is processed by a publishing tool. |
| Repository | A project managed by Git. |
| Review | The process of checking documentation for quality, accuracy, consistency, and completeness. |
| Review artifact | A file that records the result of a review, including scores and recommendations. |
| Reviewer | A person who checks content against a rubric or a set of rules, and decides whether it is ready. |
| Role | The responsibility of an agent in a workflow. |
| Rollback | Restoring the previous version of published content after a bad change has been published. |
| RTCCO framework | A prompt structure with five parts: Role, Task, Context, Constraints, and Output. |
| Runner | The virtual machine that runs a job in a workflow, such as ubuntu-latest. |
| Runtime | Software that provides the environment required to execute a program. |

## S

| Term | Definition |
| --- | --- |
| Secret | An encrypted value, such as a token, stored in GitHub and passed to a workflow without being shown in logs. |
| Session | One period of work with Claude Code, from the moment you start it until you exit. |
| Severity | A rating of how much harm a defect can cause a reader, used to decide what to fix first. |
| Skill | A set of reusable instructions for one kind of task, which an AI tool loads when the task matches. |
| SKILL.md | The main file of a skill. It holds a short name and description, and the instructions the AI follows. |
| Slash command | A short name that starts a saved request or workflow, such as /review. |
| Source Control | The VS Code interface for working with version control systems such as Git. |
| Source of truth | The authoritative location where information should be maintained. |
| Spell checker | A tool that compares each word with a dictionary, and flags words it does not recognize. |
| SSH | A secure protocol that can be used to authenticate Git operations. |
| Step | One task inside a job in a workflow, run with a command or a reusable action. |
| Stop condition | A defined situation in which an automated or AI step must stop and report, instead of continuing. |
| Subcommand | The action that a tool performs, such as run in npm run or status in git status. |
| Syntax highlighting | Visual formatting that helps readers distinguish different parts of code. |

## T

| Term | Definition |
| --- | --- |
| Terminal | A text-based interface used to run commands. |
| Terminology | The words and terms used to describe a product, feature, process, or concept. |
| Terminology drift | The gradual inconsistency of terms across a documentation set, usually caused by terms added without a shared record. |
| Tip | A callout used to provide useful advice or a recommended practice. |
| Tool | An external system or connector that an agent can call, such as an API connector. |
| Translation | Changing the words of content from one language to another. |
| Triage | The process of sorting each finding into an outcome, such as valid, not valid, or needing an owner. |
| Trigger | An event that starts a specific automated workflow or task. |
| Troubleshooting | The process of identifying and resolving a problem. |
| Type check | A check that code uses its types correctly, such as the `npm run typecheck` command in this project. |

## V

| Term | Definition |
| --- | --- |
| Validation | Checking that content, code, or data follows the defined rules before it is used or published. |
| Verification | The process of checking that a tool or system works as expected. |
| Virtual environment | An isolated Python environment used to manage project-specific packages and dependencies. |
| Visual Studio Code | A source-code editor that can also be used to create and maintain documentation. |
| VS Code | The common short name for Visual Studio Code. |

## W

| Term | Definition |
| --- | --- |
| Warning | A callout used to identify a possible problem or risk. |
| Workflow | A defined sequence of steps that runs automatically or on demand. |
| Working tree | The files you currently have checked out and are working on. |
| WSL 2 | Windows Subsystem for Linux 2, which provides a Linux environment used by Docker Desktop on Windows. |
