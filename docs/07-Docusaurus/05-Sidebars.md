## What Is a Docusaurus Sidebar?

A sidebar is the navigation menu that appears on the left side of documentation pages. It organizes all your documentation into a logical structure that helps readers find what they need.

### Sidebar Components

**Categories:**
- Groupings of related pages
- Can be collapsed/expanded
- Can be nested

**Documents:**
- Individual pages
- Links to specific files
- Can have custom labels

**Auto-generated:**
- Automatically discovers files in folders
- No manual listing needed
- Alphabetical by default

### How Sidebars Work

```
Sidebar Structure
├── Start Here (document)
├── Module 1 · Welcome (category - not collapsed)
│   ├── Overview
│   ├── Learning Path
│   └── Prerequisites
├── Module 2 · Setup (category - collapsed)
│   ├── Install Node
│   ├── Install Git
│   └── Configure Editor
└── Module 3 · Git (category - collapsed)
    ├── Branches
    ├── Commits
    └── Merging
```

Users click categories to expand/collapse. Users click documents to read.

:::important

Good sidebars make documentation easy to navigate. Poor sidebars frustrate users and make finding content difficult.

:::

## Sidebar Configuration File

The `sidebars.ts` file controls sidebar structure.

### Location

```
your-docs-repo/
├── docs/
│   ├── 01-Welcome/
│   ├── 02-Setup/
│   └── 03-Git/
├── sidebars.ts        ← This file
├── docusaurus.config.js
└── package.json
```

The `sidebars.ts` file sits in project root, not in docs folder.

### File Format

```typescript
import type { SidebarsConfig } from '@docusaurus/plugin-content-docs';

const sidebars: SidebarsConfig = {
  learningPath: [
    // Your sidebar structure here
  ],
};

export default sidebars;
```

This is TypeScript. Use `sidebars.js` if you prefer JavaScript.

## Basic Sidebar Structure

### Simple Document Link

Link to a single file:

```typescript
{
  type: 'doc',
  id: 'intro',
  label: 'Start Here',
}
```

**What it does:**
- Type: This is a single document
- ID: File path (looks for `docs/intro.md`)
- Label: Text shown in sidebar ("Start Here")

### Category with Manual Items

Group related documents:

```typescript
{
  type: 'category',
  label: 'Module 1 · Welcome',
  collapsed: false,
  items: [
    {
      type: 'doc',
      id: 'welcome/overview',
      label: 'Overview',
    },
    {
      type: 'doc',
      id: 'welcome/learning-path',
      label: 'Learning Path',
    },
  ],
}
```

**What it does:**
- Type: This is a category (folder grouping)
- Label: "Module 1 · Welcome" shown in sidebar
- Collapsed: false means expanded by default
- Items: List of documents in this category

### Category with Autogenerated Files

Let Docusaurus find files automatically:

```typescript
{
  type: 'category',
  label: 'Module 3 · Git',
  collapsed: true,
  items: [
    {
      type: 'autogenerated',
      dirName: '03-Git',
    },
  ],
}
```

**What it does:**
- Looks in `docs/03-Git/` folder
- Finds all `.md` files
- Lists them automatically
- Ordered alphabetically (by sidebar_position)
- Collapsed: true means collapsed by default

:::tip

Use autogenerated sidebars. They update automatically when you add files. No manual sidebar updates needed!

:::

## How-To: Create Your First Sidebar

### Step 1: Open sidebars.ts

Create or edit: `sidebars.ts`

```typescript
import type { SidebarsConfig } from '@docusaurus/plugin-content-docs';

const sidebars: SidebarsConfig = {
  // Sidebar name
  learningPath: [
    // Sidebar content goes here
  ],
};

export default sidebars;
```

### Step 2: Add a start document

```typescript
const sidebars: SidebarsConfig = {
  learningPath: [
    {
      type: 'doc',
      id: 'intro',
      label: 'Start Here',
    },
  ],
};
```

**Before (sidebar empty):**
Nothing shows in sidebar

**After:**
```
📄 Start Here
```

### Step 3: Add first category

```typescript
const sidebars: SidebarsConfig = {
  learningPath: [
    {
      type: 'doc',
      id: 'intro',
      label: 'Start Here',
    },
    {
      type: 'category',
      label: 'Module 1 · Welcome',
      collapsed: false,
      items: [
        {
          type: 'autogenerated',
          dirName: '00-Welcome',
        },
      ],
    },
  ],
};
```

**Before:**
```
📄 Start Here
```

**After:**
```
📄 Start Here
📁 Module 1 · Welcome (expanded)
   📄 Welcome Page
   📄 Getting Started
   📄 Prerequisites
```

### Step 4: Add more categories

```typescript
{
  type: 'category',
  label: 'Module 2 · Setup',
  collapsed: true,

  type: 'category',
  label: 'Module 3 · Git',
  collapsed: true,
  items: [
    {
      type: 'autogenerated',
      dirName: '03-Git',
    },
```

**Before:**
```
📄 Start Here
📁 Module 1 · Welcome
```

**After:**
```
📄 Start Here
📁 Module 1 · Welcome
📁 Module 2 · Setup
📁 Module 3 · Git
```

### Step 5: Test locally

```bash
npm run start
```

Visit `http://localhost:3000`

Check sidebar:
- Categories expanded correctly?
- Pages listed in right order?
- Labels showing correctly?
- Links working?

## Sidebar Configuration Options

### collapsed Property

Controls if category is expanded or collapsed by default.

```typescript
// Expanded by default (users see all items)
collapsed: false

// Collapsed by default (users click to expand)
collapsed: true
```

**Best practice:**
- First module: `collapsed: false` (welcome users, don't hide)
- Other modules: `collapsed: true` (reduce clutter)

### Sidebar Position

Control order of items using `sidebar_position` in frontmatter:

**In `docs/03-Git/Branches.md`:**

```markdown
---
title: Git Branches
sidebar_position: 1
---
```

**In `docs/03-Git/Commits.md`:**

```markdown
---
title: Git Commits
sidebar_position: 2
---
```

Branches appears before Commits (position 1 < 2)

:::tip

Always use `sidebar_position` in frontmatter. It controls order in autogenerated sidebars.

:::

### Multiple Sidebars

Create separate sidebars for different documentation:

```typescript
const sidebars: SidebarsConfig = {
  // First sidebar
  tutorial: [
    {
      type: 'category',
      label: 'Getting Started',
      items: [
        {
          type: 'autogenerated',
          dirName: 'tutorial',
        },
      ],
    },
  ],

  // Second sidebar
  api: [
    {
      type: 'category',
      label: 'API Reference',
      items: [
        {
          type: 'autogenerated',
          dirName: 'api',
        },
      ],
    },
  ],
};
```

Then in docs, specify which sidebar:

```markdown
---
sidebar_label: Authentication
sidebar_position: 1
sidebar_class: apiDoc
---
```

## Sidebar Best Practices

### Do's

✓ Use autogenerated sidebars (fewer manual updates)
✓ Use meaningful category labels
✓ Keep category depth to 2-3 levels
✓ Use `sidebar_position` in frontmatter
✓ Group related topics in categories
✓ Collapse less-used modules
✓ Test sidebar locally before deploying

### Don'ts

✗ Don't nest too deeply (more than 3 levels confusing)
✗ Don't use generic labels ("Module 1", "Section A")
✗ Don't manually list all files (use autogenerated)
✗ Don't forget `sidebar_position` (files appear in wrong order)
✗ Don't expand all categories (overwhelming to users)
