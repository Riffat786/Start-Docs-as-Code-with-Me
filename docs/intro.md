# Welcome to Start Docs-as-Code with Me

Welcome to **Start Docs-as-Code with Me** — a practical learning platform for Technical Writers and documentation professionals who want to build confidence with modern documentation tools and workflows.

I created this project to bring together the things I use and continue to learn as a Technical Writer: structured content, Git, GitHub, Docs-as-Code, API documentation, automation, and AI.

The focus is simple: **learn by doing**.

Rather than working through tools in isolation, you will build a documentation project as you progress through the modules. You will write Markdown, work with Git and GitHub, build and publish a documentation website, explore API documentation, and gradually introduce automation and AI into the workflow.

The aim is not to turn Technical Writers into developers. It is to help documentation professionals become more comfortable working alongside development teams and with the tools that support modern software documentation.

---

Throughout the learning path, you will work with:

# How You'll Learn

The learning approach is straightforward:

**Learn → Practice → Build**

Each module combines explanation with practical work.

You will find:

- Concepts explained in plain language
- Step-by-step instructions
- Practical examples
- Hands-on exercises
- Best practices
- Troubleshooting guidance
- Knowledge checks
- Real-world projects

The intention is that you should be able to follow an instruction, understand why you are doing it, and troubleshoot it when something does not work as expected.

# AI and This Project

AI is deliberately part of this learning journey.

As documentation professionals, we are already seeing AI change how we research, write, review, structure, and maintain documentation. Learning how to use these tools responsibly is becoming an important part of modern technical writing.

AI has also been used to help build this documentation portfolio.

I have used AI tools during the development of this project to explore ideas, create and refine content, troubleshoot code, develop components, and experiment with AI-assisted documentation workflows.

The purpose is not to present AI-generated content as finished work.

The Technical Writer still has to make the decisions.

That means reviewing the output, checking technical accuracy, improving the writing, considering the audience, and deciding what belongs in the final documentation.

This project is therefore also a practical demonstration of **AI skills applied to technical documentation**.

You will see examples of this approach throughout the learning path, particularly in the modules covering AI, automation, and real-world projects.

# A Note for Other Technical Writers

This project is also my way of sharing what I am learning.

Documentation tools and practices continue to change, and none of us needs to know everything before we start. The goal here is to learn in public, try things out, document what works, and share the lessons along the way.

If you are a Technical Writer who has mostly worked with traditional documentation tools, some of these topics may initially feel unfamiliar.

That's okay.

**Start with Markdown. Learn Git. Create a repository.**
> **Make a change. Build something. Break it. Fix it.**

That is how this project is being built too.
